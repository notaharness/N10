Closes #153

The "N unresolved" count in a pull request tab's header is a button that takes you to the threads it counts.

## Header button

`components/review/PrHeader.tsx` renders the count as `UnresolvedButton`, a real `<button>` whose accessible name and tooltip read "Show N unresolved comments".

## Revealing the first open thread

`lib/review/use-review-rail.ts` (`useReviewRail`) owns the rail's visibility state: rail hidden or shown, and the Comments list collapsed or expanded. Its `showUnresolved` unhides the rail, expands the list, focuses the first open thread through the comment navigator (which scrolls the diff to it and marks its rail row active), and scrolls that row into view once the click has committed.

- The count comes from the pull request list, while the threads are their own query. If the cached threads have no open thread when the button is clicked (they haven't loaded yet, or they lag the count), the click is held and the threads are refetched. It lands once they arrive, or is dropped if the fresh list has none.
- `firstUnresolvedThread` in `lib/review/review-model.ts` picks the target: the first unresolved remote thread in document order. Agent drafts are skipped, since the header count is the provider's.
- `CommentsList` takes its expanded state as props (`open`/`onOpenChange`) so the workspace can open it. Rows carry `data-comment-row` and `aria-current` for the active one.
- The hidden-rail stub moves to `CollapsedRail` in `ReviewRail.tsx`, which keeps `PrWorkspace.tsx` within the line budget.

## Tests

- `apps/desktop-e2e/src/unresolved-comments.test.ts` opens a PR whose first open thread is far down a long file, behind 40 other files. Starting from a hidden rail, and again from a collapsed Comments list, it checks that the row is active and in the viewport and that the thread card is in the viewport. A third case clicks while provider latency keeps the threads in flight.
- `review-model.spec.ts` covers `firstUnresolvedThread`.
