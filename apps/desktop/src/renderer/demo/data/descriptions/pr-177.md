A worktree's tab survives `git switch` inside the worktree, whether it is typed into n10's terminal or run from an outside shell. The tab relabels to the new branch, picks up that branch's pull request context, and keeps the agent that runs in the checkout. While the worktree is off the branch the tab was opened for, the tab shows a warning banner that names both branches.

## Root cause

Worktree rows, agent sessions and tabs were all matched to a worktree by branch. The session registry key is `['worktree', repo, branch]`, where `branch` is the branch the session was created for (`@orchestra-branch`). A sidebar row's key and session name come from the branch that is checked out now. After a switch the row moved to `branch:other`, while the agent kept running under the `feature` key that no row named. So:

- the open tab was stranded on `branch:feature`. It had no item and no label update, and its agent pane lost its session.
- the row for `other` reported no running agent, so nothing could reopen the tab. After a renderer reload the tab was gone, even though tmux still had the agent running in that worktree.

## Worktree identity by path

- **Host:** `apps/desktop/src/host/services/worktree-sessions.ts` ties each worktree row to the held agent session that runs in its directory (tmux `#{session_path}`, compared by real path). The match is applied only when the session's branch differs from the checked-out branch. `withMovedSessions` points the row's session name and `running` flag at that session and records `sessionBranch`, the branch the session was created for. It runs after `buildSidebarItems` (`services/sidebar.ts`), so the PR and orphan-PR lookups still go by the current branch: the old branch's PR shows as its own row. tmux is listed only when a live held worktree session has a key that no row matches, so an ordinary poll doesn't fork, including after a worktree whose agent ran here has been removed.
- **Row shape:** `AgentSession` gains an optional `path` and `sessionBranch` (`libs/core/src/lib/types.ts`). Session keys don't change.
- **Tabs:** item tabs record their `worktree` path. `rekey` (`lib/tabs/tab-sync.ts`, `followedKey`) follows the worktree first, even when the old key still exists (a PR row left behind by the switch), then the existing key, then the branch. `EditorArea.itemFor` resolves by worktree first for the same reason, so the render before `sync-items` catches up doesn't unmount the agent pane.
- **Left-behind rows:** a tab that followed its worktree onto another branch no longer stands for the item it was opened on (`standsFor` in `lib/tabs/tab-identity.ts`). Opening that PR row or old branch therefore gives it a tab of its own. That tab gets a free id (`tabIdFor`, with a `~n` suffix, which can't occur in a branch name or PR key) while the moved tab keeps its id, so its pane doesn't remount. `openItem`, auto-open and the palette's optimistic checkout all use the same rule.

## Banner

- The first sync records `originBranch` on the tab, taken from the row's `sessionBranch` when there is one, otherwise from its branch. A tab restored for a switched worktree's agent therefore still knows its original branch.
- `components/editor/BranchSwitchBanner.tsx` renders above the pane body while the item's branch differs from `originBranch`. It is informational and has no actions. The pane body now sits in a stable wrapper, so the banner appearing or clearing never remounts the terminal.

## Tests

- `apps/desktop-e2e/src/branch-switch.test.ts`: a switch from an outside shell, where the tab relabels, keeps its agent, survives a renderer reload with the banner, and clears the banner on switching back. A second case does the same by typing `git switch` into n10's terminal in the worktree.
- `host/services/worktree-sessions.spec.ts` and `renderer/lib/tabs/tab-worktree.spec.ts` cover the path match and the tab's follow and stamp rules.
