Part of #156 (epic #151). First pass, opened as a draft for a hands-on refinement round.

Fleet is a collapsible section of the sidebar, not a page of its own. The machines, their state, the first-run and pairing steps, add-a-machine instructions and reset all run inline beside the workspace. Revoke is the only flow in a modal.

## Sidebar section

- `components/fleet/FleetSection.tsx`: the collapsible section. Its header shows the fleet's state while collapsed: "Passkey step" while a ceremony holds a link, otherwise "Not set up", "Unavailable", "This machine" or the status bar's machine summary. The summary lives in `lib/fleet/section-summary.ts`, and the status bar's count is shared as `machinesSummary` in `lib/machines/machine-model.ts`.
- `components/sidebar/Sidebar.tsx` puts the section below the repository rows, capped at 70% of the height and scrolling inside that. `screens/RepoOpen.tsx` shows the same section in a sidebar column beside the repository picker, so fleet works before a repository is open.
- `components/fleet/FleetPanel.tsx` is the section's body. In order of precedence it shows the reset confirmation, an enrolment in progress or just finished, the first-run choices, then the fleet fingerprint, **Add a machine**, the machine rows and **Reset fleet on this machine…**. `AddMachinePanel.tsx` and `ResetFleetPanel.tsx` render inline in the section. `MachineRow.tsx` and `InboundMailPanel.tsx` are laid out for sidebar width, with the fingerprint under the state.

## State and entry points

- `lib/fleet/fleet-context.tsx` owns the section's expanded state (persisted, collapsed by default), the add-a-machine view and `reveal()`. `reveal()` shows a hidden sidebar through the host that `screens/Workspace.tsx` registers, expands the section and focuses its header. The status bar's machine segment and Settings → Machines (**Show Fleet**) call it.
- The ceremonies stay above the repository gate. Collapsing the section, hiding the sidebar or switching repositories keeps the form values and a running ceremony.
- The title-bar Fleet button and the full-screen overlay are gone. So are the palette, stepper-shortcut and menu-command special cases that existed only to step around the overlay.

## The one modal

`App.tsx` renders `RevokeMachineDialog` above the repository gate. Revoke is the only destructive passkey ceremony, and it targets a machine other than the one being looked at. The modal keeps that machine's name and fingerprint next to the confirmation, the link and the result, and it cannot be dismissed while the ceremony runs. Create and join mostly wait on another device, so blocking the workspace for them buys nothing. Reset has no passkey step, and its typed confirmation already demands attention. `docs/design/beam-fleet-ux.md` §1 records the placement and this reasoning.

## Double-click guard

In the narrow, scrolling section, the second click of a double-clicked **Create fleet** can land on the **Cancel setup** that replaces it. `CeremonyProgress.tsx` ignores clicks with `detail > 1`, so a double click starts once and never cancels.

## Tests

`apps/desktop-e2e/src/fleet-sidebar.test.ts` covers the section on the picker screen and the workspace staying usable during a ceremony. It also checks that a ceremony survives collapsing the section and hiding the sidebar, that the status bar and Settings reveal a hidden sidebar, and that a revocation survives a repository switch. The other fleet specs use the section through `setup/machines.ts`.
