Linux installers for n10 Desktop, a .deb and an AppImage, plus the handling the app needs to run as an installed app. This covers steps 1–3 of #122. The npm package's `n10` launches the same way it does today.

## Packaged-mode behavior

`apps/desktop/src/main/launch-env.ts` works out how the app was started:

- **Version and dev menu.** The app identifies its build by manifest name. `n10-dev` is the dev build. Anything else reports `app.getVersion()`, meaning the npm package or an installer. `app.isPackaged` can't be used here because it is also false under the npm package. `N10_DESKTOP_VERSION` is now only a label that e2e, QA and perf runs set, and the launcher no longer passes it.
- **Start directory.** `N10_START_DIR` still decides when it is set, as the npm launcher and the tests do. Otherwise an installed app opens its last path argument (a `file://` URI from the desktop entry counts), and the cwd only when a terminal started it. `main.ts` reads the variable once and removes it, so sessions never inherit it. `openStartupRepo` (`host/services/repo.ts`) takes the resolved directory.
- **Login-shell PATH.** When an installed app has no terminal on stdin (a desktop menu or the Dock), it runs `$SHELL -ilc`, reads `printenv PATH` between marks, and puts that PATH first. This happens before beam, tmux or any session starts. The shell is SIGKILLed after 5 s.
- **Missing tmux.** The tmux check runs right after the PATH import, before beam starts. Without tmux, the startup error dialog gives the reason and the install hint, then the app quits.
- **Beam path.** `beam/paths.ts` `unpackedPath` maps the beam binary to `app.asar.unpacked`, both for the daemon and for the session bin's `beam` symlink. The `n10` session shim runs from inside the asar through Electron as Node, so the RunAsNode fuse stays enabled.

`main.ts` moved its `N10_QA_STEPS` runner into `qa-steps.ts` to stay within the line budget.

## Icons

`apps/desktop/build/icon.svg` is the website's `n10-mark.svg`. `scripts/icons.sh` renders it with Inkscape into `build/icon.png` (1024) and `build/icons/NxN.png` for Linux. The PNGs are committed.

## Linux packages

`npx nx package-linux desktop` builds both packages into `apps/desktop/dist/installers`. CI can call this target.

- `scripts/package-linux.mjs` stages `dist/installer-app`. It uses the npm package's layout (`desktop/{main,preload,renderer}`) and version, and a manifest named `n10` with `desktopName`. node-pty (with the addon built here, minus sources and other platforms' prebuilds) and beam with its one installed platform package are copied from the workspace. The package therefore holds only the host architecture's binaries. The script fails if node-pty's Linux addon wasn't built. Arm64 is built on an arm64 runner.
- `electron-builder.yml`:
  - `asarUnpack` covers node-pty and `@notaharness/beam-*`.
  - The executable is `n10-desktop`, so the deb's `/usr/bin` link never shadows the npm package's `n10`.
  - `n10.desktop` is synced to Electron's app_id.
  - The deb depends on `tmux (>= 3.2)`, `git` and `libasound2t64 | libasound2` (ALSA, which minimal systems lack), plus electron-builder's defaults.
  - On Ubuntu 24.04+ the deb installs electron-builder's AppArmor profile, and the AppImage's launcher adds `--no-sandbox` where user namespaces are blocked.

Sizes (x64): deb 95 MB, AppImage 121 MB.

Docs: `docs/decisions.md` (packaging section), `docs/architecture.md`, `apps/desktop/AGENTS.md`.

## Verified by hand

- **.deb in a clean `ubuntu:24.04` container**, launched under Xvfb with stdin not a TTY and the repo as an argument:
  - `apt install` pulls in tmux and git.
  - The app reports `1.0.0-beta.1`, opens the repo and launches a shell terminal.
  - In that tmux session, PATH is `~/.config/n10/bin:<dir from ~/.bashrc>:/usr/bin:/bin`, `n10 util` runs the shim, and `beam version` prints `0.1.0-beta.3`.
  - With tmux removed, the startup error dialog appears.
- **AppImage on the host** under Xvfb with `--no-sandbox`: same results while the app runs.

## Known limitations

- An AppImage's session bin points into its FUSE mount. `n10 util` and `beam` in sessions that outlive it fail until it runs again. The deb has fixed paths.
- A second launch with a path argument only focuses the running window (#173).
- The installers don't provide the `n10` command (`--tui`, `util` outside sessions). That still needs the npm package.
